## 4. 当前最关键缺口判断

按「缺了就不能跑 Demo 主线」排序：

### 1. 没有「灰桥镇」开局场景
- `TownScene.ts` 当前是通用城镇 UI，不是灰桥镇开局叙事。
- 没有「我是商队队长、带着余烬核心、要去点亮大安」的叙事入口。
- 没有开局对话 / 教学引导 / 第一笔主线订单。

### 2. 没有「余烬核心」主线状态字段
- `GameState.ts` 中没有 `emberCoreStatus`（未携带 / 携带中 / 已点亮大安 / 已点亮第二城）等字段。
- 没有相关事件、触发点、UI 提示。

### 3. 没有 Demo 中型地图结构
- 现有 3 条 `cityRoutes`（灰烬驿城 / 矿炉城 / 药泉城）不是 Demo 需要的「灰桥镇 → 第一驿站 → 大安 → 大安周边 → 中程商路 → 第二城」结构。
- 没有区域路线图（世界视角）数据。
- 没有「路线解锁」状态。

### 4. 没有「第一驿站」中继点
- 第一驿站是灰桥镇到大安之间的教学中继，未实现。
- 需要补给/修车/休整/天气提示的基础功能。

### 5. 没有「大安点亮」流程
- 现有城市复兴是被动自建 + 订单加成的数值系统，没有「玩家带着余烬核心到达大安 → 点亮大安」的叙事流程。
- 没有到达判定、核心激活、视觉反馈。

### 6. 没有「商队账本」
- Demo 核心体验之一是「玩家通过账本知道自己在做什么、下一步做什么」。
- 当前没有任何账本 UI / 信息边界 / 主线提示 / 远方传闻。

### 7. 没有「士气 / 扎营 v1」
- `GameState` 有 `morale` 字段，但没有完整数值系统、降低/回复触发逻辑。
- 没有扎营场景。
- 没有失败条件（补给归零 / 士气归零 / 货车损毁）。

### 8. 没有「车队牌 / 货车战斗资源」
- 当前货车只是 `caravanHp` 一条数值，没有车队牌系统。
- 没有货车冲撞、车灯照射、车棚加固等战斗资源。

### 9. 没有「从开局到第二城点亮」的完整流程测试
- 现有 smoke test 只覆盖单个系统或单段流程（订单交付、货物准备、工具系统、城市复兴）。
- 没有端到端主流程测试（灰桥镇 → 教学路 → 第一驿站 → 大安 → 短途经营 → 中程商路 → 第二城）。

### 10. 城市命名不匹配 Demo 设定
- 现有：灰烬驿城 / 矿炉城 / 药泉城。
- Demo 需要：灰桥镇 / 大安 / 第二城（未定名）。
- 这不是大问题，但会影响数据文件（`cityRoutes.ts` / `cityOrders.ts` / `cityRevivalSystem.ts`）的可读性和扩展方式。

## 5. Demo 中型地图建议落点

### 5.1 现有 MapScene 是否适合继续承载 Demo 中型地图

**结论：适合作为「局部远行地图」继续复用，但不适合作为整张大地图。**

- `MapScene.ts` 已经有：格子地图生成、`canMoveTo` 动态移动判断、目标节点（订单交付）、战斗节点触发、事件节点、撤退/再来一局接入、城市复兴奖励加成。
- 这层逻辑可以直接作为「一段远征路线的局部地图」复用（例如 N3.1 教学路、N3.2 半随机路线、大安周边短途、中程商路的每一段）。
- 但 `MapScene` 没有「区域路线图」概念，也没有「选择下一段路线」的 UI，不能单独撑起整个 Demo 世界地图。

### 5.2 是否需要新增 `demoWorldMap` 数据文件

**建议：新增。**

- 现有 `cityRoutes.ts` 是「3 条商路 → 3 个城市」扁平结构。
- Demo 需要多层结构：灰桥镇（起点镇） → 第一驿站（中继点） → 大安（目标城 1） → 大安周边（开放区） → 中程商路 → 第二城（目标城 2）。
- 建议新增 `src/data/demoWorldMap.ts`，定义：
  - **节点（node）**：灰桥镇、第一驿站、大安、大安周边村庄 A/B、中程驿站、第二城。
  - **连接（link）**：节点之间的路线段，含路线 id、长度、风险、推荐货物。
  - **路线解锁状态**：哪些路线默认开放，哪些需要完成前置（例如完成 N3.1 才解锁大安、完成大安点亮才解锁大安周边等）。
  - **每段路线对应远征地图参数**：地图尺寸、敌人密度、补给密度、事件密度。
- 这个数据文件和 `cityRoutes.ts` 的关系：初期可以并行存在，`cityRoutes.ts` 作为旧内容保留；等 Demo 路线稳定后再决定是否合并或删除旧路线。

### 5.3 是否需要新增区域路线系统

**建议：新增，但放在 C1 阶段做基础，后续阶段逐步完善。**

- C1 中至少需要：
  - 区域路线图节点数据结构（见 5.2）。
  - 路线图渲染场景（`WorldMapScene` 重构或新增 `RegionMapScene`）：显示节点、连接、玩家当前所在节点、已解锁/未解锁状态。
  - 点击节点 → 进入该段路线的「局部远征地图」（复用现有 `MapScene` 逻辑，按 demoWorldMap 中的参数生成）。
  - 完成一段远征后 → 返回路线图并更新玩家位置。
- C6/C9 阶段再增加：短途路线、中程商路分段、风险评估显示等。

### 5.4 是否先做「区域路线图 + 局部远行地图」两层结构

**强烈建议：先做两层结构。**

这是最符合 Demo 叙事的做法：

- **上层（区域路线图）**：显示「我在哪、能去哪、每条路线有什么风险和收益」。玩家在这里选择下一段目标。
- **下层（局部远征地图）**：进入一段远征时的细粒度格子地图，玩家一格一格走、打战斗、做事件、交付订单。

两层结构比直接做一张 20×20 的完整大地图更合理：
- Demo 主线是分段叙事（教学路 → 驿站 → 大安 → 周边 → 中程 → 第二城），每段叙事可以对应一张局部远征地图。
- 玩家在一张超大自由地图上容易迷路（和「信息边界」理念冲突）。
- 现有 `MapScene` 逻辑可以直接复用为下层，工作量可控。

### 5.5 是否暂不做完整世界大地图

**建议：暂不做。**

- 完整九城世界大地图是最终目标，不是 Demo 目标。
- Demo 只需要「灰桥镇 → 大安 → 第二城」这一条主线 + 周边开放区。
- 等 Demo 闭环可玩后，再扩展更多城市和路线。

### 5.6 灰桥镇、第一驿站、大安、第二城方向如何落入数据结构

建议在 `demoWorldMap.ts` 中按节点分层：

```
  - node_first_outpost     // 第一驿站

      类型: city
      功能: 交易 + 订单 + 工坊 + 城市复兴状态展示
  - node_da_an_village_a   // 大安周边村庄 A
      类型: village
      功能: 短途订单起点/终点
  - node_da_an_village_b   // 大安周边村庄 B
      类型: village
  - node_mid_post_a        // 中程商路中继 A
      类型: outpost
  - node_mid_post_b        // 中程商路中继 B
      类型: outpost
  - node_second_city       // 第二座城市
      类型: city

路线段（link / route segment）:
  - seg_graybridge_to_outpost   // N3.1 固定教学路
  - seg_outpost_to_da_an        // N3.2 半随机路线
  - seg_da_an_to_village_a      // 大安周边短途 A
  - seg_da_an_to_village_b      // 大安周边短途 B
  - seg_da_an_to_mid_a          // 中程商路第一段
  - ...

解锁条件（unlockCondition）:
  - 默认解锁: seg_graybridge_to_outpost
  - 到达第一驿站后解锁: seg_outpost_to_da_an
  - 大安点亮后解锁: seg_da_an_to_village_a, seg_da_an_to_village_b
  - 大安 level >= 1 后解锁: seg_da_an_to_mid_a（中程商路）
  - ...
```

`GameState` 中需要新增：

- `currentNodeId: string` — 当前所在节点。
- `unlockedNodeIds: string[]` — 已解锁节点。
- `unlockedRouteSegmentIds: string[]` — 已解锁路线段。
- `emberCoreStatus` — 余烬核心状态（未携带 / 携带中 / 已点亮大安 / 已点亮第二城）。
- `visitedNodeIds: string[]` — 已访问过的节点（用于账本显示）。

## 6. D1/D2 前必须补齐的 blocker

| Blocker | 严重程度 | 影响 | 建议解决阶段 |
| --- | --- | --- | --- |
| 没有灰桥镇开局场景与叙事 | **P0** | 玩家不知道自己是谁、为什么出发、要去哪里 | C2 / 或 C1 作为 Demo 地图数据的一部分 |

| 没有区域路线图场景（上层地图） | **P0** | 玩家无法选择下一段路线；没有「从哪到哪」的导航 | C1 |
| 没有第一驿站中继点 | **P1** | 灰桥镇到大安之间缺少教学缓冲和休整点 | C4 |
| 没有大安点亮流程 | **P1** | Demo 第一个核心叙事节点不成立 | C5 |
| 没有商队账本与信息边界 | **P1** | 玩家容易迷路；没有主线提示；Demo 信息边界理念不成立 | C8 |
| 没有士气 / 扎营 / 撤退 v1 完整系统 | **P1** | 远行生存压力不成立；失败条件不完整 | C7 |
| 现有城市命名与 Demo 设定不匹配 | **P2** | 影响代码可读性和数据扩展；不阻塞功能但建议在 C1 统一命名 | C1（数据结构定义时统一） |
| WorldMapScene 是独立原型未接入主系统 | **P2** | 可以不用它；但如果要改造成区域路线图需要重构 | C1（要么重构要么重写） |
| 没有端到端主流程 smoke test | **P2** | 开发过程中难以及时发现回归问题 | C6/C10 之后补齐 |
| 没有车队牌 / 货车战斗资源 | **P3** | 货车只是一条 hp，没有商队特色战斗资源 | C8 阶段按需 |
| build chunk size 警告（>500KB） | **P3** | 不影响功能；可在 Demo 收口阶段做代码分割 | 最后优化 |

**严重程度定义：**
- **P0**：不解决就无法继续 Demo 主线。
- **P1**：不解决会严重影响第一版 Demo。
- **P2**：可暂时绕过，但后续必须解决。
- **P3**：体验优化或文档问题。

## 8. 建议下一步

### 明确结论

**C0 验收通过：现有基础底座足够支撑第一版 Demo 开发，可以进入 C1。**

当前已经有一个稳定的「路线选择 → 角色选择 → 货物准备 → 地图探索 → 战斗 → 订单交付 → 再来一局 → 城市复兴跨局保留」最小闭环，核心系统（地图、战斗、订单、货物准备、工具、城市复兴）全部 smoke test 全绿，`npm run build` 无报错。

当前**没有发现**需要紧急修复的基础 bug（build 成功、核心测试全绿）。

### 下一步优先级

建议下一步按以下顺序推进：

1. **C1：Demo 中型地图底座**（最高优先级）
   - 新增 `src/data/demoWorldMap.ts`：灰桥镇 / 第一驿站 / 大安 / 大安周边村庄 / 中程中继 / 第二城 的节点与路线段数据结构。
   - 新增或重构区域路线图场景：上层地图（节点 + 连接 + 解锁状态），点击节点进入下层局部远征地图。
   - 复用现有 `MapScene` 作为下层局部远征地图。
   - 在 `GameState` 中新增 `currentNodeId` / `unlockedNodeIds` / `unlockedRouteSegmentIds` / `emberCoreStatus` / `visitedNodeIds` 等字段。
   - 在 C1 阶段只做「能选择路线段并进入局部地图」，不实现灰桥镇叙事、大安点亮等内容（留到 C2/C5）。

2. **C2：灰桥镇开局与余烬核心主线状态**
   - 在 C1 地图底座落地后再做。

3. **C0b：不需要**
   - 本次 C0 审查没有发现需要在 C1 之前修复的 P0 blocker。
   - 所有 P0 blocker 本身就是 C1/C2 的实现内容（demoWorldMap 数据结构、区域路线图、余烬核心状态字段等），不需要额外插一条「先修 bug 再开发」的阶段。

### 为什么不直接进入 C2

- C2 依赖 C1 的数据结构（没有 demoWorldMap 就没有「灰桥镇节点」、没有「路线解锁」）。
- 如果在没有地图底座的情况下先写灰桥镇叙事和 UI，后续会面临「把硬编码内容重构到数据驱动结构」的返工。
- 先落地 C1 底座，再在上面叠加 C2-C10 的叙事和功能，更符合「每个阶段都能单独验收、单独试玩」的开发原则。
